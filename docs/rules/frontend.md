# Frontend 지침 (Next.js BFF)

Next.js(App Router) + TypeScript. `web`은 화면이면서 **BFF**다. 책임은 두 가지: 인증/토큰 관리, 여러 API의 데이터 조합. 설계 근거는 `docs/architecture.md` 7~8장, 세션·갱신·조합 API 결정은 [ADR 0022](../adr/0022-bff-session-and-aggregation-apis.md), 연동 계약은 [integrations.md](../architecture/integrations.md)다.

Next.js는 버전 간 변화가 크다(현재 16.x: 미들웨어는 `proxy.ts`). 캐싱, 쿠키, Route Handler, `proxy` 관련 API는 `web/node_modules/next/dist/docs/`의 설치된 버전 문서로 확인하고 작성한다 (`web/AGENTS.md`).

## 디렉터리

```
web/src
├── proxy.ts             라우트 보호용 사전 리다이렉트 (인가 아님, 아래 참고)
├── app/                 라우트, 레이아웃, Route Handler
│   └── api/             브라우저가 호출하는 BFF 엔드포인트 (얇게: 검증 → 서버 함수 호출 → 응답)
├── server/              서버 전용 코드 (import 'server-only')
│   ├── env.ts           서버 환경 변수 (zod 검증)
│   ├── auth/            세션, 토큰 보관·갱신, CSRF
│   ├── api/             Gateway 호출 클라이언트 (도메인별)
│   └── aggregate/       화면 단위 조합 함수
├── features/            기능별 UI와 클라이언트 로직 (booking, stream, ...)
├── components/          범용 UI 컴포넌트
└── lib/                 서버·클라이언트 공용 순수 유틸, 타입
```

- `server/` 아래 모든 파일은 `import 'server-only'`로 시작한다. 클라이언트 컴포넌트에서 import하면 빌드가 실패해야 한다.
- `lib/`에는 서버 전용 모듈(세션, 환경 변수, Gateway 클라이언트)을 두지 않는다. 클라이언트 번들에 섞이면 안 되는 코드는 `server/`로 간다.
- 서버 환경 변수는 `server/env.ts`에서 한 번 검증하고 `process.env`를 직접 읽지 않는다.

## 토큰과 세션 (최우선 규칙)

- **JWT(access/refresh)는 브라우저에 절대 전달하지 않는다.** 응답 본문, 클라이언트 컴포넌트 props, `NEXT_PUBLIC_*` 환경 변수, 브라우저 저장소, URL, 로그 어디에도 두지 않는다. 오류 응답과 로그에 토큰·`Authorization` 헤더를 그대로 싣지 않는다.
- 브라우저에는 불투명 세션 ID 쿠키(`ticketing_session`)만 내려간다: `HttpOnly`, `SameSite=Lax`, `Path=/`, 만료 14일. `Secure`는 운영 환경에서 필수이며 로컬 HTTP 개발에서만 `SESSION_COOKIE_SECURE=false`로 끈다.
- 토큰은 서버 측 세션(Redis `bff:session:<sessionId>`, TTL 14일)에 둔다. 세션을 다루는 코드는 `server/auth/`에만 둔다. 프로세스 메모리나 암호화 쿠키에 토큰을 두지 않는다.
- 갱신은 `server/api/`의 공통 클라이언트가 서버에서 처리한다. access 만료 30초 전이거나 백엔드가 401을 반환하면 갱신한다.
- **갱신은 세션당 한 번만** 일어나게 한다(프로세스 내 single-flight + Redis 락). refresh 토큰은 로테이션되고 재사용이 감지되면 회원의 모든 refresh 토큰이 폐기되므로, 동시 갱신은 성능이 아니라 정합성 문제다.
- 갱신 실패 시 세션을 파기하고 로그인으로 보낸다.
- 로그아웃은 코어의 refresh 토큰 폐기 API를 호출한 뒤 세션을 지운다. 폐기 호출이 실패해도 BFF 세션은 지운다.
- 상태를 바꾸는 요청(Route Handler의 POST 등, Server Action)은 CSRF 방어를 적용한다 (`Origin`을 `WEB_ORIGIN`과 대조). 새 변경 엔드포인트를 추가할 때 검증을 빠뜨리지 않는다.
- `proxy.ts`는 쿠키가 없을 때 로그인으로 보내는 UX용 리다이렉트일 뿐이다. 쿠키 존재만 보며 세션 유효성이나 권한을 보증하지 않는다. 세션 확인은 `server/auth/`의 함수(`requireUser` 등)로 서버에서 한다.
- 화면에서 메뉴를 숨기는 것은 편의일 뿐이다. 인가는 백엔드가 강제하며, BFF는 백엔드의 401/403을 그대로 반영한다.

## 백엔드 호출

- 브라우저는 백엔드(Gateway)를 직접 호출하지 않는다. **유일한 예외는 SSE**다.
- Gateway 호출은 `server/api/`의 클라이언트로만 한다. 컴포넌트나 Route Handler에서 `fetch`로 Gateway URL을 직접 부르지 않는다.
- Gateway 주소 등 서버 설정은 `NEXT_PUBLIC_` 접두어 없는 환경 변수로 둔다. 브라우저가 SSE로 접속할 공개 주소만 별도 값(`GATEWAY_PUBLIC_URL`)으로 구분하되, 토큰·비밀은 담지 않는다.
- 백엔드 응답은 경계에서 스키마(zod)로 검증하고 타입을 얻는다. `any`와 타입 단언(`as`)으로 넘기지 않는다.
- 백엔드 오류는 `ProblemDetail`의 `code`로 분기한다. 메시지 문자열로 분기하지 않는다. 브라우저로는 화면에 필요한 코드와 안내 문구만 내리고 백엔드 내부 메시지·스택을 그대로 전달하지 않는다.
- 사용자별 데이터는 캐시하지 않는다(`no-store`). 공연 목록 같은 공개 데이터만 재검증 주기를 두고 캐시한다. 캐시 여부는 공통 클라이언트 호출 옵션으로 명시한다.
- 모든 Gateway 호출에 타임아웃을 둔다. 기본값은 공통 클라이언트가 정하고(현재 3초), 부가 데이터는 더 짧게 줄 수 있다. 타임아웃·연결 실패는 5xx와 같은 "일시 오류"로 다룬다.
- 결제·예매 생성 요청에는 `Idempotency-Key`를 붙인다. 키는 사용자 의도 한 건당 하나를 만들고, 재시도·재제출 시 같은 키를 쓴다. 요청마다 새 키를 만들지 않는다.
- 결제 요청의 헤더 키는 계약상 필수값이며 코어는 값을 검증만 한다. 결제 멱등성은 예매 ID를 기준으로 보장하고 PG에는 코어가 만든 `booking-<id>` 키를 사용한다.
- 예매 생성에는 입장 토큰을 `X-Admission-Token` 헤더로 전달한다. 입장 토큰은 JWT가 아닌 불투명 난수로, 브라우저가 대기열 SSE로 받아 BFF에 넘긴다. 검증은 Gateway의 책임이며 BFF는 토큰 형식을 해석하지 않는다.

## 조합 (Aggregation)

- 화면 하나에 필요한 데이터 조합은 `server/aggregate/`의 함수 하나로 만든다 (예: `getPerformanceDetail`, `getMyPage`, `getOrganizerDashboard`).
- 독립적인 하위 호출은 병렬로 보낸다(`Promise.all`/`allSettled`). 순차 `await`로 폭포를 만들지 않는다. 앞선 결과가 필요한 호출만 순차로 한다.
- **부분 실패를 허용한다.** 핵심 데이터(공연 정보)가 실패하면 전체 실패, 부가 데이터(잔여 좌석, 내 예매 여부)가 실패하면 해당 부분만 비운 채 응답한다. 어느 쪽이 핵심인지 조합 함수에 명시하고, 비운 부분을 화면이 구분할 수 있게 결과 타입에 표현한다(빈 목록과 "조회 실패"를 혼동하지 않는다).
- 단, 401/403은 부분 실패로 삼키지 않는다. 인증 오류는 부가 데이터라도 세션 처리로 전파한다.
- 하위 호출마다 타임아웃을 둔다. 핵심 호출이 부가 호출보다 오래 기다릴 수 있다.
- 조합 결과는 화면에 필요한 형태로 가공한 타입이다. 백엔드 응답을 그대로 이어 붙여 내보내지 않는다.
- 조합에 필요한 조회가 기존 API로 정확히 만들어지지 않으면 근사하지 말고 소유 모듈에 API 추가를 제안한다(ADR 0022). 조인을 BFF에서 흉내 내지 않는다.

## SSE

- SSE는 BFF를 거치지 않고 브라우저가 Gateway에 직접 연결한다 (Node 프로세스가 장기 연결을 붙들지 않기 위함).
- 연결 전 BFF의 엔드포인트(`/api/streams/tickets`)에서 **단기 SSE 티켓**을 받아 사용한다. JWT를 URL이나 헤더에 싣지 않는다.
- 티켓은 **1회용이며 수명이 짧다**(30초). 재연결할 때마다 새로 받는다. 브라우저 `EventSource`의 자동 재연결은 같은 URL(소비된 티켓)을 재사용하므로 의존하지 않고, 훅이 연결을 닫고 새 티켓으로 직접 다시 연다.
- `EventSource`는 `Last-Event-ID` 헤더를 직접 실을 수 없으므로, 재연결할 때 마지막으로 받은 이벤트 ID를 `?lastEventId=` 쿼리로 넘겨 이어 받는다.
- SSE 연결은 `features/stream/`의 훅으로 감싼다. 언마운트 시 반드시 연결을 닫고, 대기 중인 재연결 타이머도 정리한다.
- 재연결은 지수 백오프(상한과 지터 포함)로 한다. 인증 실패 등 재시도해도 소용없는 종료와 일시 오류를 구분한다.
- 좌석 화면은 접속 시 스냅샷을 받고 이후 변경분을 적용한다. 화면의 좌석 상태는 표시용이며, 선점 성공 여부는 서버 응답으로만 판단한다.

## 컴포넌트

- 한 파일이 여러 화면 단계나 독립적인 상태·동작을 함께 담당하면 기능별 컴포넌트나 훅으로 분리한다. 500줄을 넘으면 책임 분리를 검토하되, 줄 수만 맞추려고 응집된 코드를 쪼개지 않는다. 공통 타입과 경계 검증은 기능 디렉터리 안에 둔다.
- 기본은 Server Component. `'use client'`는 상호작용이나 브라우저 API가 필요한 최소 단위에만 붙인다.
- 데이터 조회는 Server Component에서 조합 함수를 호출해 한다. 클라이언트에서 `useEffect`로 초기 데이터를 가져오지 않는다.
- 변경(예매, 취소, 로그인)은 Server Action 또는 Route Handler로 한다. 폼 제출처럼 화면에 묶인 변경은 Server Action, 클라이언트가 직접 호출해야 하는 것(SSE 티켓 발급 등)은 Route Handler를 쓴다. 둘 다 같은 `server/` 함수를 호출하고 CSRF 검증은 동일하게 적용한다.
- Server Component에서 클라이언트 컴포넌트로 넘기는 props는 화면에 필요한 값만 담는다. 세션 객체나 백엔드 응답 원본을 통째로 넘기지 않는다(토큰 노출 경로가 된다).
- 라우트마다 `loading`과 `error` 경계를 둔다. `error` 경계는 내부 오류 메시지를 노출하지 않는다.
- 서버 상태를 전역 클라이언트 스토어에 복사하지 않는다. 클라이언트 상태는 UI 상태(선택한 좌석, 모달)로 한정한다.

## 예매 화면 규칙

- 선점 남은 시간은 서버가 준 만료 시각 기준으로 표시한다. 클라이언트에서 5분을 따로 세지 않는다. 기기 시계 오차가 클 수 있으므로 서버 시각 기준 차이로 남은 시간을 계산한다.
- 결제·예매 버튼은 요청 중 비활성화하고, 중복 제출을 막는다. 비활성화는 편의이며 중복 방지는 코어의 멱등 처리에 의존한다.
- 오류 코드별 안내를 구분한다: 좌석 선점 실패, 선점 만료, 입장 토큰 만료(대기열로 복귀), 결제 실패. 새 오류 코드를 안내 없이 일반 오류로 삼키지 않는다.

## TypeScript와 스타일

- 화면 구성과 시각 규칙은 [UI 가이드](../ui-guide.md)를 따른다.
- `strict` 모드. `any` 금지, `as` 단언은 사유 주석과 함께 최소화한다.
- 컴포넌트는 함수 선언과 named export. 기본 export는 Next.js가 요구하는 파일(`page`, `layout`, `proxy` 등)에만 쓴다. (`proxy.ts`는 named `proxy` export를 쓰는 Next 규약을 따른다.)
- 파일명은 kebab-case, 컴포넌트 이름은 PascalCase.
- ESLint와 Prettier 설정을 따르고 규칙을 끄는 주석을 임의로 넣지 않는다.
- 시맨틱 마크업과 키보드 조작을 기본으로 한다. 좌석 버튼에는 좌석 번호와 상태를 읽을 수 있는 레이블을 준다.

## 테스트

- 조합 함수와 토큰 갱신 로직: 단위 테스트. 하위 API를 가짜로 두고 부분 실패, 타임아웃, 동시 갱신, 갱신 실패 시 세션 파기를 검증한다.
- SSE 훅: 재연결(새 티켓, 백오프, `lastEventId`)과 언마운트 시 연결 종료를 검증한다.
- 변경 엔드포인트: Origin 검증(허용/거부)과 미인증 응답을 검증한다.
- 컴포넌트: 사용자 관점의 동작 위주로 테스트한다.
- E2E(Playwright): 로그인 → 대기열 → 좌석 선택 → 결제 → 예매 완료.
- 토큰 비노출 검증: E2E에서 브라우저 저장소와 네트워크 응답에 JWT가 없음을 확인한다 (M4 완료 기준).
- 실행: `./scripts/agent/test/web-check.sh [--build]`
- 실행: `./scripts/e2e/run.sh --web`
