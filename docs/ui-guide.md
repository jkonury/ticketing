# UI 가이드

공연을 탐색하고 지정석을 예매하는 화면의 시각·상호작용 기준이다. 첨부된 현재 공연 목록, 공연 상세, 로그인 화면을 바탕으로 작성한 **적용 제안**이며, 아직 구현된 디자인 시스템을 뜻하지 않는다. 데이터와 예매 동작은 기존 서비스 계약과 [프런트엔드 지침](./rules/frontend.md)을 따른다.

## 디자인 방향

- 공연 정보와 다음 행동을 먼저 보여 주는 차분한 화면을 만든다. 장식보다 제목, 장소, 날짜, 가격의 위계를 우선한다.
- 흰색 표면과 밝은 회색 배경 위에 짙은 남색 텍스트와 선명한 파란색 행동 버튼을 사용한다. 공연 이미지가 없는 데이터는 제목과 장소가 있는 카드로 표현하고 임의의 포스터를 만들지 않는다.
- 한 화면에서 가장 중요한 행동 하나를 강조한다. 상세 화면에서는 회차별 예매, 로그인 화면에서는 로그인이다.

## 공통 시각 규칙

아래 값은 구현 시 출발점이다. 동일한 역할에는 동일한 토큰을 적용한다.

| 역할 | 값 | 사용처 |
|---|---|---|
| 배경 | `#F7F8FA` | 페이지 배경 |
| 표면 | `#FFFFFF` | 카드, 입력창 |
| 기본 글자 | `#172033` | 제목, 본문 |
| 보조 글자 | `#526077` | 장소, 부가 설명 |
| 테두리 | `#D5DCE5` | 입력창, 구분선 |
| 강조 | `#1D4ED8` | 주요 버튼, 링크, 선택 |
| 오류 | `#B42318` | 오류 메시지와 상태 |
| 성공 | `#067647` | 완료 상태 |

기본 서체는 시스템 산세리프를 사용한다. 본문은 16px / 줄 높이 1.5, 페이지 제목은 28px / 1.3, 섹션 제목은 20px / 1.4, 보조 정보는 14px / 1.5를 기준으로 한다. 날짜·가격·잔여 좌석은 줄바꿈되어도 단위를 함께 읽을 수 있게 한다. 금액은 천 단위 쉼표와 원을, 날짜는 서울 시간 기준을 유지한다.

간격은 4px 단위를 사용한다. 입력 항목 사이는 16px, 카드 내부는 20~24px, 주요 섹션 사이는 32~48px을 기준으로 한다. 카드는 12px, 버튼과 입력창은 8px 모서리를 사용하고, 옅은 테두리로 구분한다. 그림자는 필요한 경우에만 약하게 쓴다.

## 레이아웃과 탐색

- 공통 헤더에는 왼쪽에 홈으로 가는 서비스명, 오른쪽에 로그인 또는 현재 사용자 메뉴를 배치한다. 메뉴는 역할에 따라 기존 마이페이지 또는 주최자 메뉴를 제공한다.
- 본문 최대 너비는 1120px, 좌우 여백은 모바일 16px, 넓은 화면 24px 이상이다. 로그인·회원 가입 폼은 최대 440px로 제한한다.
- 768px 미만은 단일 열, 768px 이상은 공간에 따라 목록을 2~3열로 표시한다. 화면 확대와 긴 한국어 텍스트에도 가로 스크롤이 생기지 않도록 한다. 좌석 배치처럼 넓이가 필요한 영역은 스크롤 가능함을 표시한다.
- 링크는 이동, 버튼은 현재 화면에서의 동작에 사용한다. 모든 페이지에 주제에 맞는 제목 하나를 두고 섹션 제목을 순서대로 배치한다.

## 화면별 구성

### 공연 목록

상단에 `공연 목록` 제목을 두고 공연을 카드 목록으로 표시한다. 각 카드에는 공연명, 장소, 첫 회차 일시를 순서대로 넣는다. 회차가 없으면 `회차 미정`을 표시한다. 공연명 또는 카드의 명확한 링크로 상세 화면에 이동한다. 다음 페이지가 있을 때만 목록 아래에 `더 보기`를 둔다. 결과가 없으면 `등록된 공연이 없습니다`를 보여 준다.

### 공연 상세

공연명, 소개, 공연장 순으로 소개 영역을 구성한다. 그 아래 가격을 등급별 행으로 정렬해 등급과 금액을 쉽게 비교하게 한다. 회차는 날짜·시간, 잔여 좌석, `예매하기`를 묶은 행이나 카드로 표시한다. 넓은 화면에서는 정보와 버튼을 가로로, 모바일에서는 세로로 놓는다.

잔여 좌석이 0이면 `매진`을 표시하고 예매 버튼을 비활성화한다. 잔여 좌석 조회가 실패한 경우 `잔여 좌석 확인 불가`를 표시하며 0석으로 오인시키지 않는다. 내 예매 정보가 있으면 별도 안내로 표시하고, 조회 실패 시 해당 정보만 확인할 수 없다고 알린다. 핵심 공연 정보를 불러오지 못한 경우 전체 오류와 재시도 수단을 제공한다.

### 로그인과 회원 가입

중앙의 좁은 폼에 제목, 필드, 주요 버튼, 보조 링크 순으로 배치한다. 레이블은 입력창 위에 항상 표시한다. 이메일과 비밀번호를 한 줄에 나란히 두지 않는다. 회원 가입에는 기존 이름과 역할 선택을 추가한다. 비밀번호 조건은 입력 전에 알리고, 제출 실패 메시지는 폼 안에서 확인할 수 있게 한다. 제출 중에는 버튼을 비활성화하고 진행 중임을 표시한다.

### 예매 흐름

대기열, 좌석 선택, 결제, 완료의 현재 단계를 제목으로 분명하게 표시한다. 대기열은 순번과 연결 상태를 강조한다. 좌석 선택은 공연과 회차, 최대 선택 수, 좌석 상태 범례, 선택 결과와 다음 행동을 함께 보여 준다. 좌석의 선택 가능·선점 중·판매 완료·내 선택 상태는 색뿐 아니라 텍스트 또는 모양으로도 구분한다.

결제 화면은 선택 결과, 금액, 서버 만료 시각에 따른 남은 시간과 결제 행동을 보여 준다. 만료 및 결제 실패 시 이유와 가능한 다음 행동을 안내한다. 완료 화면은 예매 번호, 좌석, 금액을 우선 표시한다. 좌석 현황은 표시용이며 실제 선점 및 확정 결과는 서버 응답을 따른다.

### 마이페이지와 주최자 화면

예매와 결제 상태는 읽기 쉬운 텍스트로 구분하고, 취소처럼 결과가 큰 행동은 해당 항목 가까이에 둔다. 결제 정보의 부분 실패는 나머지 예매 정보와 분리해 알린다. 주최자 화면의 판매·정산 정보와 등록 폼에도 같은 제목, 표, 입력 규칙을 적용한다. 좁은 화면에서 표가 잘리지 않도록 스크롤 또는 항목별 배치를 제공한다.

## 컴포넌트와 상태

- **버튼:** 주요 행동은 강조색 배경과 흰 글자, 보조 행동은 흰 배경과 테두리로 구분한다. 높이는 최소 44px로 한다. 기본·호버·포커스·비활성·처리 중 상태를 제공하고, 비활성 이유가 필요하면 주변에 설명한다.
- **입력:** 레이블, 입력창, 도움말 또는 오류 순으로 묶는다. 입력창 높이는 최소 44px로 하고 오류는 색과 문구로 표시한다. 오류 메시지를 해당 필드와 연결한다.
- **피드백:** 로딩, 빈 결과, 오류, 부분 실패를 각각 구분한다. 오류는 무엇을 할 수 있는지 안내하고, 재시도가 가능한 경우 재시도 수단을 제공한다. 완료와 실패를 색상만으로 구별하지 않는다.
- **접근성:** 텍스트 대비는 일반 텍스트 4.5:1 이상, 큰 텍스트 3:1 이상을 목표로 한다. 키보드만으로 모든 기능을 이용할 수 있어야 하며, 포커스는 주변과 구별되는 외곽선으로 표시한다. 상태 변화와 오류는 보조기술에도 알리고, 자동 갱신되는 순번이나 남은 시간은 과도하게 반복해서 읽지 않도록 한다.

## 적용 확인

1. 320px 폭부터 데스크톱까지 목록·상세·로그인 화면의 정보가 겹치거나 잘리지 않는지 확인한다.
2. 키보드로 헤더, 링크, 폼, 좌석, 주요 버튼에 순서대로 접근하고 포커스를 확인한다.
3. 빈 목록, 매진, 잔여 좌석 조회 실패, 로그인 오류, 요청 중, 선점 만료와 결제 실패를 확인한다.
4. 실제 화면 변경 시 기존 예매·인증 흐름과 프런트엔드 지침의 테스트를 함께 확인한다.
