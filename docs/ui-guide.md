# UI 가이드

공연을 탐색하고 지정석을 예매하는 화면의 시각·상호작용 기준이다. 방향과 근거는 [ADR 0049](./adr/0049-ui-redesign-direction.md), 진행 상황은 [UI 개편 로드맵](./ui/roadmap.md)에 있다. 아래 값은 U1에서 토큰으로 구현하며, 구현 전까지는 목표 기준이다. 데이터와 예매 동작은 기존 서비스 계약과 [프런트엔드 지침](./rules/frontend.md)을 따른다.

## 디자인 방향

- 서비스 표시 이름은 "오픈석"이다. 헤더에는 워드마크만 둔다.
- 정보 밀도가 높은 밝은 커머스형 화면이다. 포스터, 제목, 일시, 장소, 가격의 위계를 우선한다.
- 모바일을 먼저 설계한다. 좌석 선택 화면만 데스크톱 레이아웃을 따로 설계한다.
- 대기열, 좌석 경합, 선점 만료처럼 실시간으로 바뀌는 상태를 눈에 보이게 한다. 모션은 이런 곳에만 쓴다.
- 한 화면에서 가장 중요한 행동 하나를 primary로 강조한다.
- 포스터 이미지가 없는 공연은 공연 ID와 제목으로 결정적으로 생성한 그래픽 포스터를 쓴다. 같은 공연은 항상 같은 그래픽이다.

## 공통 시각 규칙

토큰은 시맨틱 이름으로 정의하고 화면 코드에서 색 값을 직접 쓰지 않는다. 라이트 테마만 제공하되, 다크 테마를 토큰 값만으로 추가할 수 있게 이름을 짓는다. 값과 이름은 `web/src/app/globals.css`의 `@theme`가 원본이다. 브랜드는 [시안](./ui/mockups/brand.html)의 A안(`#4338CA`, 호버 `#3730A3`, 연한 배경 `#E0E7FF`)으로 확정했다.

| 역할 | 기준 | 사용처 |
|---|---|---|
| 배경 | 밝은 회색 | 페이지 배경 |
| 표면 | 흰색 | 카드, 입력창, 시트 |
| 기본 글자 | 짙은 남색 | 제목, 본문 |
| 보조 글자 | 회청색 | 장소, 부가 설명 |
| 테두리 | 옅은 회색 | 입력창, 구분선 |
| 브랜드 | 인디고 `#4338CA` 계열 | primary 버튼, 링크, 내 선택 좌석 |
| 경고 | 앰버 | 다른 사용자 선점, 선점 만료 임박 |
| 오류 | 빨강 | 오류 메시지, danger 버튼 |
| 성공 | 초록 | 완료 상태 배지. 좌석 상태에는 쓰지 않는다 |

서체는 Pretendard 서브셋 정적 폰트(400·600·700·800)를 셀프 호스팅하고 미리 받지 않는다. 서브셋에 없는 드문 글자는 시스템 글꼴로 표시된다. 본문은 16px / 줄 높이 1.5, 페이지 제목은 28px / 1.3, 섹션 제목은 20px / 1.4, 보조 정보는 14px / 1.5를 기준으로 한다. 가격·순번·남은 시간처럼 바뀌는 숫자는 고정폭 숫자(`tabular-nums`)로 표시한다. 금액은 천 단위 쉼표와 원을, 날짜는 서울 시간 기준을 유지한다.

간격은 4px 단위를 사용한다. 입력 항목 사이는 16px, 카드 내부는 16~24px, 주요 섹션 사이는 32~48px을 기준으로 한다. 카드는 12px, 버튼과 입력창은 8px 모서리를 쓰고, 옅은 테두리로 구분한다. 그림자는 고정 바, 시트, 다이얼로그처럼 떠 있는 요소에만 쓴다.

아이콘은 `lucide-react`를 쓴다. 문구는 해요체로 통일한다.

## 레이아웃과 탐색

- 헤더는 모바일에서 한 줄이다. 왼쪽에 워드마크, 오른쪽에 로그인 또는 메뉴 버튼을 두고, 메뉴는 시트로 연다. 사용자 이름 옆에 역할 코드를 노출하지 않고, 주최자와 관리자만 배지를 붙인다.
- 본문 최대 너비는 1120px, 좌우 여백은 모바일 16px, 넓은 화면 24px 이상이다. 로그인·회원 가입 폼은 최대 440px로 제한한다.
- 공연 목록은 모바일 2열, 넓은 화면 3~4열 그리드다. 화면 확대와 긴 한국어 텍스트에도 가로 스크롤이 생기지 않게 한다.
- 모바일에서 표는 카드 목록으로 바꾼다. 어떤 열도 잘려서 동작에 접근할 수 없게 되면 안 된다.
- 링크는 이동, 버튼은 현재 화면에서의 동작에 사용한다. 모든 페이지에 주제에 맞는 제목 하나를 두고 섹션 제목을 순서대로 배치한다.

## 화면별 구성

### 공연 목록

포스터 카드 그리드로 표시한다. 카드에는 포스터, 공연명, 장소, 첫 회차 일시를 순서대로 넣는다. 회차가 없으면 `회차 미정`을 표시한다. 카드 전체가 상세로 가는 하나의 링크다. 다음 페이지가 있을 때만 목록 아래에 `더 보기`를 둔다. 결과가 없으면 공통 빈 상태로 `등록된 공연이 없어요`를 보여 준다. 장르 탭은 장르 데이터가 생긴 뒤(U4) 추가한다.

### 공연 상세

포스터와 공연명, 장소, 소개를 위에 두고, 그 아래에 등급별 가격표와 회차 카드를 둔다. 회차 카드는 날짜·시간, 잔여 좌석, `예매하기`를 묶는다. 넓은 화면에서는 포스터와 정보를 가로로, 모바일에서는 세로로 놓는다.

잔여 좌석이 0이면 `매진`을 표시하고 예매 버튼을 비활성화한다. 잔여 좌석 조회가 실패한 경우 `잔여 좌석 확인 불가`를 표시하며 0석으로 오인시키지 않는다. 내 예매 정보가 있으면 별도 안내로 표시하고, 조회 실패 시 해당 정보만 확인할 수 없다고 알린다. 핵심 공연 정보를 불러오지 못한 경우 전체 오류와 재시도 수단을 제공한다.

### 로그인과 회원 가입

중앙의 좁은 폼에 제목, 필드, 주요 버튼, 보조 링크 순으로 배치한다. 레이블은 입력창 위에 항상 표시한다. 회원 가입에는 이름과 역할 선택을 둔다. 비밀번호 조건은 입력 전에 알리고, 제출 실패 메시지는 폼 안에서 확인할 수 있게 한다. 제출 중에는 버튼을 비활성화하고 진행 중임을 표시한다.

### 대기열

내 순번을 가장 크게 보여 주고, 앞에 남은 인원, 예상 대기 시간, 진행 바, 공연·회차 요약을 함께 둔다. "새로고침하면 순번이 뒤로 밀릴 수 있어요" 안내와 연결 상태를 표시한다. 순번이 줄어들 때 숫자 전환 모션을 쓴다. 순번 변화를 보조기술에 매번 읽히지 않도록 일정 간격으로만 알린다.

### 좌석 선택

- 좌석은 글자 없는 작은 칩이다. 위쪽에 무대 표시, 아래쪽에 범례를 둔다. 등급은 구역 머리의 등급·가격 범례로 구분하고, 좌석 색은 상태에만 쓴다.
- 상태는 색과 모양을 함께 쓴다: 선택 가능(흰 바탕, 테두리), 내 선택(브랜드 채움, 체크), 다른 사용자 선점(앰버, 빗금), 판매됨(회색, X).
- 좌석에 포커스하거나 탭하면 `A구역 1열 3번 · VIP 150,000원` 형태의 툴팁을 보여 준다. 같은 내용을 접근성 레이블로 준다.
- 좌석 그리드는 roving tabindex로 탭 정지 하나만 갖고, 방향키로 좌석 사이를 이동한다.
- 다른 사용자가 선점하면 해당 좌석을 잠깐 강조한다.
- 모바일은 화면 폭에 맞춰 전체 배치를 보여 주고 확대 토글을 둔다. 하단 고정 바에 선택 수, 합계 금액, `예매하기`를 둔다.
- 데스크톱은 오른쪽 고정 패널에 선택 좌석 목록, 등급별 금액, 합계, `예매하기`를 둔다.
- 좌석 현황은 표시용이며 실제 선점 및 확정 결과는 서버 응답을 따른다.

### 결제

선택 좌석, 금액, 쿠폰, 남은 시간을 보여 준다. 남은 시간은 서버 만료 시각 기준 `mm:ss` 카운트다운과 줄어드는 진행 바로 표시한다. 60초가 남으면 앰버로 바꾸고 한 번 알린다. 만료되면 다이얼로그로 알리고 좌석 선택으로 돌려보낸다. `결제하기`는 primary, `취소`는 secondary다. 결제 중에는 진행 표시를 보여 준다. 결제 실패 시 이유와 가능한 다음 행동을 안내한다.

### 예매 완료

티켓 모양 카드에 포스터 썸네일, 공연명, 일시, 공연장, 좌석, 금액, 예매 번호를 보여 준다. 입장 기능이 없으므로 QR 코드는 넣지 않는다.

### 마이페이지와 쿠폰

예매는 카드 목록으로 보여 주고 예매·결제 상태를 배지로 구분한다. 예매 취소는 danger 버튼이며 확인 다이얼로그를 거친다. 결제 정보의 부분 실패는 나머지 예매 정보와 분리해 알린다. 쿠폰은 할인 내용과 기한이 보이는 쿠폰 카드로 보여 준다.

### 주최자·관리자 화면

상단에 판매율, 매출, 잔여석 같은 지표 카드를 두고 그 아래 전체 폭 표를 둔다. 빈 표에는 공통 빈 상태를 보여 준다. 공연 등록 폼은 넓은 화면에서 2열이며 좌석 배치 미리보기를 함께 보여 준다. 차트는 두지 않는다.

## 컴포넌트와 상태

- **버튼:** primary(브랜드 배경, 흰 글자), secondary(흰 배경, 테두리), ghost(배경 없음), danger(오류 색) 네 단계다. 높이는 최소 44px이다. 기본·호버·포커스·비활성·처리 중 상태를 제공하고, 비활성 이유가 필요하면 주변에 설명한다.
- **입력:** 레이블, 입력창, 도움말 또는 오류 순으로 묶는다. 입력창 높이는 최소 44px로 하고 오류는 색과 문구로 표시한다. 오류 메시지를 해당 필드와 연결한다.
- **피드백:** 빈 상태, 로딩(스켈레톤), 오류, 부분 실패는 공통 컴포넌트로 표시한다. 오류는 무엇을 할 수 있는지 안내하고, 재시도가 가능한 경우 재시도 수단을 제공한다. 일시적인 결과 알림은 토스트로 한다. 완료와 실패를 색상만으로 구별하지 않는다.
- **오버레이:** 다이얼로그, 시트, 토스트는 Radix 프리미티브를 감싸 쓴다. 포커스 가두기와 복귀, Esc 닫기를 보장한다.
- **모션:** 순번 감소, 선점 반영, 선점 타이머처럼 실시간 상태에만 쓴다. `prefers-reduced-motion`이면 끈다.
- **접근성:** WCAG 2.2 AA가 목표다. 텍스트 대비는 일반 텍스트 4.5:1 이상, 큰 텍스트 3:1 이상이다. 키보드만으로 모든 기능을 이용할 수 있어야 하며, 포커스는 주변과 구별되는 외곽선으로 표시한다. 상태 변화와 오류는 보조기술에도 알리고, 자동 갱신되는 순번이나 남은 시간은 과도하게 반복해서 읽지 않게 한다.

## 적용 확인

1. 320px 폭부터 데스크톱까지 정보가 겹치거나 잘리지 않는지 확인한다. 전체 흐름 캡처는 모바일 390px, 데스크톱 1440px로 한다.
2. 키보드로 헤더, 링크, 폼, 좌석 그리드(방향키), 주요 버튼에 순서대로 접근하고 포커스를 확인한다.
3. 빈 목록, 매진, 잔여 좌석 조회 실패, 로그인 오류, 요청 중, 대기 순번, 선점 만료 임박·만료, 결제 실패를 확인한다.
4. `@axe-core/playwright` 검사에서 위반이 없어야 한다.
5. 실제 화면 변경 시 기존 예매·인증 흐름과 프런트엔드 지침의 테스트를 함께 확인한다.
