# M5-2 개선 및 측정 인계

## Step 1: 측정 공백 보완 (검증 미완료)

### 구현 및 지표 해석

- `queue.registration`은 대기열 신규 등록, 기존 대기자 재등록, 이미 입장한 회원의 재등록을 구분한다. `queue.departure`는 실제 대기열 제거 건수로 명시 이탈, 생존 신호 없음, 유예 초과를 구분한다. 입장 Lua는 실제 검사 건수와 제거 건수, 조회 키 생성 건수를 반환한다. `queue.admission`은 조회 키 생성과 Gateway 검증 키 준비 성공·실패를 구분한다. 입장 배치·스케줄러 시작 간격·생존 신호 갱신은 타이머로 기록한다.
- 모든 태그는 제한된 결과와 사유만 사용한다. 인스턴스별 카운터를 합산해야 하며 Redis 스크립트는 한 번의 실제 변경만 반환한다. 프로세스 중단이나 Redis 응답 유실 시 변경은 발생했어도 카운터가 빠질 수 있으므로 이 지표는 정합성 원장이 아니다. Gateway 키 기록이 중간 실패하면 생성된 조회 키 수와 준비된 키 수가 다를 수 있다.
- Gateway `spring.cloud.gateway.requests` 경로별 히스토그램과 Reactor Netty 연결 풀의 active·idle·pending 및 획득 대기를 수집한다. 경로 태그에 사용자 URL을 추가하지 않는다. 코어 `hikaricp.connections.acquire` 버킷과 기존 평균·최대·pending·timeout을 보존한다. 5초 게이지는 순간 급증을 놓칠 수 있으므로 타이머와 JFR을 함께 해석한다.
- k6는 등록·티켓 발급·예매·결제·상세의 전체 실행 Trend와 등록·입장·정시 준비·지각 준비·예매 시도·예매 생성·결제 요청·확정 흐름을 기록한다. 각 Trend는 모든 시도의 HTTP duration이며 SSE 유지 시간이 아니다. `resources.csv`는 1초 간격이다. k6 CPU는 사용한 논리 코어 수(1.0은 한 코어 전체), 호스트 CPU는 전체 논리 코어의 busy 비율이고 RSS·메모리는 바이트다.
- [Spring Boot Metrics](https://docs.spring.io/spring-boot/reference/actuator/metrics.html), [Gateway Metrics](https://docs.spring.io/spring-cloud-gateway/reference/spring-cloud-gateway-server-webflux/global-filters.html), [Redis Lua](https://redis.io/docs/latest/develop/programmability/eval-intro/) 공식 문서와 실제 Gateway 5.0.4 설정 메타데이터를 확인했다.

### 검증과 실패 이력

- 전체 테스트와 `ktlintCheck detekt` 통과. 최초 detekt는 예외 범위 규칙에 실패했고 예외를 다시 전파하도록 고친 뒤 재실행해 통과했다.
- E2E는 8082 포트 점유로 최초 실행하지 못했다. 두 번째 realtime 포트 설정을 추가해 18082로 재시도했다. Docker buildx의 읽기 전용 홈과 PostgreSQL 암호 불일치로 각각 실패한 뒤 임시 Docker 설정 디렉터리와 `.env`의 로컬 접속 정보로 재실행해 통과했다. 로그: `build/e2e/logs/`.
- 셸 구문 검사와 Python 컴파일 검사 통과. smoke `build/loadtest/runs/20261113-133617-smoke/1` 통과: Gateway route 버킷 69개, Hikari 버킷 69개, 연결 풀 지표 노출. smoke는 1초 미만이라 자원 파일에 표본이 없다.
- 이전 smoke `build/loadtest/runs/20261113-132427-smoke/`는 상속된 Redis 호스트가 로컬이 아니어서 중단했다(종료 130). 로컬 호스트로 재시도한 실행은 포트 8000 점유로 시작 전에 실패했다. E2E 직후 smoke 최초 재시도는 E2E가 띄운 fake-pg의 8090 포트 점유로 시작하지 못했다.
- A 1회차 Prometheus 추출은 인자 길이 제한으로 실패했다. 추출 스크립트를 수정하고 보존된 원시 시계열에서 자원 표본의 시작·종료 시각을 이용해 복구했다. 복구 구간에는 약 1~2초 오차가 있으며 원래 실패 로그도 보존했다.

B의 지각 준비 및 매진 이탈은 summary에 지표가 없어 값 없음으로 둔다. 세 회차 모두 1,000명 정시 준비에 미달해 온전한 1,000명 동시 경합의 성능 합격 근거가 아니다. A 중앙값은 p95 15.46ms, 오류 7.97%, SSE 99.739%, HTTP 138.85 RPS이고 B 중앙값은 각각 474.99ms, 43.69%, 36.620%, 33.33 RPS다. A는 p95만, B는 2회차 p95만 잠정 기준을 통과했다.

M5-1 A 중앙값 p95 14.3ms, 오류 7.65%, SSE 99.72%, 138.7 RPS와 차이가 있지만 부하 도달 인원과 실행 간 변동이 있어 관측 비용만의 효과로 단정할 수 없다. M5-1의 등록·입장 인원은 직접 기록되지 않아 차이를 계산할 수 없다. M5-1 B의 예매 p95는 1초 구간 p95의 중앙값이므로 이번 실행 전체 p95와 직접 비교할 수 없다.

k6 평균 CPU 코어 수는 A 0.57·0.55·0.58, B 0.05·0.05·0.06이고 호스트 평균 busy 비율은 A 25·24·25%, B 8·7·9%다. 표본별 RSS와 메모리는 각 CSV를 참고한다. 히스토그램과 연결 풀, 대기열 지표는 각 `prometheus.json`에 수록했다.

### 남은 확인

정상 입장·seen 없음·명시 이탈은 고정 입력 테스트로 검증했다. 유예 초과 제거의 상태 테스트는 있지만 해당 카운터의 고정 입력 일치 검증은 추가로 필요하다. 실행별 측정 구간과 k6 종료 코드가 각 실행 디렉터리에 명시적으로 기록되지 않아 공통 측정 계약도 아직 완전하게 충족하지 못했다. 따라서 Step 1 완료로 표시하지 않으며 Step 2는 시작하지 않는다.
