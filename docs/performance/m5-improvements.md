# M5-2 개선 및 측정 인계

M5-2(병목 개선과 전후 비교)의 허브 문서다. 단계별 측정·변경 기록은 [`m5/`](m5/) 아래 파일로 나눴고, 이 문서에는 현재 상태, 결과 요약, 판정 기준, 파일 목록만 둔다. 실행 순서와 결과 확인 방법은 [로컬 부하 테스트 실행 절차](loadtest-runbook.md)를 따른다.

## 현재 상태

2026-11-14 최종 측정(Step 8) 기준이며 2026-11-15에 문서를 정리했다.

- **M5 완료 기준 충족**: 부하 중 좌석 중복 판매 0건, 개선 전후 수치 문서화. 로드맵 M5 항목은 체크되어 있다.
- **미해결**: B 예매 생성 p95 잠정 기준 300ms 미달. 콜드 B 중앙값 1,385.3ms(3회 모두 미달), 워밍업 B 중앙값 383.3ms(3회 모두 미달). 원인은 확정하지 못했다. 정황은 폭주 약 3초 구간의 CPU 포화, 콜드 클래스 로딩·초기화, 연결 보유 시간 증가다.
- **임시 기준**: 1,000명 동시 도착은 p95 1,500ms로 판정한다(`loadtest/lib/options.ts`의 `STRESS_BOOKING_P95_MS`). 로드맵 완료 기준과 무관한 값이며 300ms는 후속 튜닝 목표로 남아 있다.
- **콜드 A(10,000명)**: 예매 p95 중앙값 110.8ms, 예상 밖 오류 0%, SSE 성공 100%, 입장 10,000명 전원으로 잠정 기준을 달성했다.
- **정합성**: 전 실행에서 중복 판매 0건, DB·Redis 불일치 0건이다.

2026-11-15 추가 측정: [Gatling Scouter ON/OFF 비교](scouter-gatling-comparison.md). 두 시나리오를 ON/OFF 각각 3회 실행했다. 현재 설정에서도 ON 비용이 남았으며, 기존 k6 기준과 별도 계열로 기록한다.

## 계열별 최종 판정

| 계열 | 예매 p95 < 300ms | 오류율 < 1% | SSE > 99.9% | 중복 판매·정합성 |
|---|---|---|---|---|
| 콜드 A (10,000명) | 달성 (110.8ms, 3/3) | 달성 (0%) | 달성 (100%) | 통과 |
| 콜드 B (1,000명) | 미달 (1,385.3ms, 0/3) | 달성 (0%) | 달성 (100%) | 통과. 임시 1,500ms 통과 |
| 워밍업 B (5회 예열) | 미달 (383.3ms, 0/3) | 달성 (0%) | 달성 (100%) | 통과. 임시 1,500ms 통과 |

- 계열 사이의 개선율은 계산하지 않는다. 콜드와 워밍업은 예열 효과이며 서버 개선이 아니다. Scouter 활성 계열(Step 2·3·5)과 비활성 계열(Step 6·7·8)도 섞어 비교하지 않는다.
- 같은 조건에서 직접 확인된 전후 효과는 Step 2의 A 오류 제거(404·`removed`·결과 없이 종료 0건)뿐이다.

## 공통 측정 조건

- A: 10,000명, 입장 배치 50, 5,000석·핫 좌석 100석. 기준 3회.
- B: 1,000명, 입장 배치 1,000, 5,000석·핫 좌석 100석. 기준 3회.
- 50명 조건: `hot-seats --vus 50`으로 입장 배치 규모 기준을 따로 본다(300ms 기준 적용).
- 잠정 기준: 예매 생성 p95 < 300ms, 예상 밖 오류율 < 1%, SSE 연결 성공률 > 99.9%. 1,000명은 p95 임시 1,500ms.
- 콜드는 앱을 매번 새로 띄우고 워밍업 요청을 보내지 않는다. 워밍업은 같은 앱에 5회 예열한 뒤 새 회차로 본 측정한다.
- 실행 디렉터리는 `build/loadtest/runs/` 아래에 있으며 대용량 산출물은 git에 넣지 않는다.

## 정정과 갱신 이력

- **콜드 스타트 결론 정정**: 1회 워밍업 기준의 "콜드 스타트는 주원인이 아니다"는 15회 예열 실험(Step A, p95 274ms)으로 정정했다. 콜드 상태에서 코드 실행 비용이 p95의 큰 몫이다. 원인을 확정한 것은 아니다. → [04](m5/04-1000-user-steps-a-c.md)
- **JIT 결론 정정**: 같은 맥락에서 "JIT는 주원인으로 확정하지 못한다"도 1회 워밍업 기준이었음을 명시했다. → [03](m5/03-1000-user-diagnosis.md), [04](m5/04-1000-user-steps-a-c.md)
- **Step 1 제목**: 원문 "(검증 미완료)"를 "(완료 표시 없음)"으로 바꿨다. 본문의 판정 문구는 기록 당시 기준이다. → [01](m5/01-step1-measurement-gaps.md)
- **문서 구성**: 865행짜리 단일 파일을 허브와 `m5/` 아래 11개 파일로 나눴다. 본문 내용은 그대로 옮겼고 상대 경로만 고쳤다. 로드맵, 런북, 계획 문서, ADR 0026의 링크를 새 위치로 갱신했다.
- 파일 안의 "체크박스는 갱신하지 않았다", "다음 step은 시작하지 않는다" 같은 문구는 해당 시점의 판정이다. 최신 상태는 이 허브와 로드맵을 따른다.
