# 대기열 순번 UI 확인

실행 중인 서비스의 기존 회차에 가상 대기자를 먼저 등록하고 브라우저에서 같은 회차를 열어 순번 변화를 확인한다. 가상 사용자는 대기 상태를 5초마다 조회해 존재를 유지하며 입장되면 종료한다. 좌석 선점이나 결제는 하지 않는다.

1. `.env`를 준비하고 PostgreSQL, Redis, core, realtime, gateway, web을 실행한다. 회차의 좌석 스냅샷이 생성되어 있어야 한다.
2. 브라우저에서 일반 사용자로 로그인하고 확인할 회차의 ID를 준비한다(예매 링크 `/booking/123`의 `123`). 부하 테스트용 `load-숫자@loadtest.local` 계정은 사용하지 않는다.
3. 저장소 루트에서 실행한 뒤 대기 인원이 충분하다는 안내가 나오면 브라우저로 해당 회차의 예매 화면에 진입한다.

   ```bash
   ./scripts/loadtest/queue-ui.sh <회차 ID> [가상 사용자 수]
   # 예: ./scripts/loadtest/queue-ui.sh 1 3000
   ```

기본 3,000명은 기본 입장 속도(초당 최대 50명)에서 약 1분 분량이다. 등록과 처리 속도에 따라 실제 대기 시간은 달라진다. 너무 빨리 입장하면 인원을 늘리고, 입장 처리량을 따로 설정했다면 그에 맞춰 조절한다. 게이트웨이 주소가 다르면 `BASE_URL` 환경 변수로 지정한다. 기존 회원 시드와 k6 빌드에 Docker가 필요하다.

재실행 시 선택된 가상 회원의 이전 대기·입장 상태는 초기화한다. 확인용 사용자에게 같은 회차의 입장 토큰이 남아 있으면 대기열을 거치지 않으므로 토큰이 만료된 뒤 다시 시도하거나 다른 사용자 또는 회차를 사용한다. 기본 입장 토큰 유효기간은 10분이다.

가상 회원은 로컬 DB에 남고 발급된 입장 토큰은 만료된다. 실행을 중단하면 남은 대기자는 존재 유예 시간 이후 입장 처리 중 제거된다. 실제 사용자가 이용 중인 환경에서는 실행하지 않는다.
