## 배경

M4에서 만든 web 화면은 기능 검증이 목적이었다. 전체 흐름을 headless 브라우저로 캡처해 보니 다음 문제가 있었다.

- 시각 위계가 없다. 모든 버튼이 같은 파란 primary라 결제와 취소, 예매 취소(파괴적 동작)가 구분되지 않는다.
- 프로젝트의 차별점이 화면에 드러나지 않는다. 좌석 맵은 `A 1-1 (VIP)` 텍스트 버튼 격자이고 범례, 무대 방향, 합계 금액이 없다. 선점 남은 시간은 `300초` 텍스트다.
- 모바일에서 기능이 깨진다. 마이페이지 표의 취소 열이 잘려 모바일에서 취소할 수 없고, 좌석 맵은 구역이 잘린 채 가로 스크롤된다.
- 스타일이 `globals.css`의 직접 작성한 클래스에 모여 있다. Tailwind 4는 import만 했고 토큰과 컴포넌트 계층이 없다.
- 공연 데이터에 포스터와 장르가 없어 커머스형 목록을 만들 재료가 없다.

개편의 목적은 세 가지다. 포트폴리오 첫인상, 대기열·좌석 경합·선점 만료 같은 실시간성을 사용자가 이해하는 예매 UX, 디자인 시스템 설계 학습이다.

## 결정

1. 범위는 web 전체(사용자 흐름, 주최자, 관리자)다. 모바일 우선으로 설계하고, 좌석 선택 화면만 데스크톱 레이아웃을 따로 설계한다.
2. 톤은 정보 밀도가 높은 밝은 커머스형이다. 라이트 테마만 출시하되 토큰은 시맨틱 이름(`surface`, `text-muted` 등)으로 지어 다크 테마를 나중에 토큰 값만으로 추가할 수 있게 한다.
3. 서비스 표시 이름은 "오픈석"(OPENSEAT)이다. 워드마크만 쓰고 심볼은 만들지 않는다. 이름은 web의 설정 한 곳에 두고 저장소·패키지·모듈 이름은 바꾸지 않는다.
4. 브랜드 컬러는 인디고(`#4338CA` 계열)다. 좌석 상태는 색과 모양을 함께 쓴다.
   - 선택 가능: 흰 바탕과 테두리
   - 내 선택: 브랜드 컬러 채움과 체크 표시
   - 다른 사용자 선점: 앰버와 빗금
   - 판매됨: 회색과 X 표시
   - 빨강은 오류 전용이고 초록은 좌석 상태에 쓰지 않는다.
5. 스타일은 Tailwind 4 `@theme` 토큰 → 프리미티브(Button, Input, Badge, Card 등) → 기능 컴포넌트 계층으로 직접 만든다. 다이얼로그, 시트, 토스트처럼 접근성 구현이 까다로운 것만 Radix 프리미티브를 감싸 쓴다. 아이콘은 `lucide-react`, 서체는 Pretendard 가변 폰트를 `next/font/local`로 셀프 호스팅한다.
6. 접근성 목표는 WCAG 2.2 AA다. 좌석 맵은 DOM 버튼 그리드에 roving tabindex를 적용해 방향키로 이동하고, 좌석마다 위치·등급·가격·상태 레이블을 둔다. 자동 검사는 `@axe-core/playwright`로 한다.
7. 모션은 실시간성을 드러내는 곳에만 CSS로 쓴다. 대상은 대기 순번 감소, 다른 사용자 선점 반영, 선점 타이머다. `prefers-reduced-motion`을 따른다.
8. 문구는 해요체로 통일한다.
9. 포스터 이미지가 없는 동안에는 공연 ID와 제목으로 결정적으로 생성한 그래픽 포스터를 쓴다. 카드 컴포넌트는 처음부터 이미지 슬롯을 두고, 실제 포스터는 [ADR 0050](0050-poster-storage-minio-presigned.md)의 저장소가 생긴 뒤 같은 슬롯에 넣는다.
10. 장르는 고정 enum(콘서트, 뮤지컬, 연극, 클래식, 스포츠, 전시)으로 `catalog.performance`에 추가한다. 컬럼은 `varchar`에 CHECK 제약을 건다.
11. 화면별 핵심 구성은 다음과 같다.
    - 좌석 선택: 글자 없는 칩, 무대 표시, 범례, 툴팁. 모바일은 화면 폭 맞춤과 확대 토글, 하단 고정 선택 요약 바. 데스크톱은 오른쪽 고정 요약 패널.
    - 결제: 서버 만료 시각 기준 `mm:ss` 카운트다운과 진행 바, 60초 남으면 앰버 경고와 `aria-live` 안내, 만료 시 다이얼로그 후 좌석 선택으로 복귀.
    - 대기열: 내 순번, 앞 인원, 예상 대기 시간, 진행 바, 새로고침 안내, 공연·회차 요약.
    - 완료: 티켓 모양 카드. 입장 기능이 없으므로 QR은 넣지 않는다.
    - 마이페이지: 카드 목록과 상태 배지. 예매 취소는 danger 버튼과 확인 다이얼로그.
    - 백오피스: 지표 카드와 전체 폭 표, 2열 등록 폼과 좌석 배치 미리보기. 차트는 넣지 않는다.
12. 버튼 위계는 primary, secondary, ghost, danger 네 단계다. 모바일 헤더는 한 줄과 시트 메뉴로 만들고 역할 코드는 노출하지 않는다(주최자·관리자만 배지). 빈 상태, 로딩, 오류는 공통 컴포넌트로 통일한다.
13. 화면 검증은 전체 흐름 캡처 스크립트로 시작하고, 디자인이 안정되면 Playwright `toHaveScreenshot()` 기준 이미지 테스트로 전환한다. 대기 순번 화면을 재현하려고 개발 환경에서 입장 속도를 낮추는 설정을 둔다.
14. 시연용 데이터는 API를 호출하는 시드 스크립트로 만들고, DB 초기화 후 시드하는 옵션을 둔다. 모듈 스키마 경계를 우회하는 SQL 직접 삽입은 쓰지 않는다.
15. 작업은 서비스 로드맵(M 트랙)과 병행하는 U 트랙([UI 개편 로드맵](../ui/roadmap.md))으로 관리한다.

## 검토한 대안

| 대안 | 채택하지 않은 이유 |
| --- | --- |
| 미니멀 프로덕트형 톤(Linear·Vercel 계열) | 이미지 없이도 완성도가 나오지만, 공연 예매 서비스다운 인상이 약하다. 사용자가 커머스형을 골랐다. |
| 다크·브랜드형 톤 | 실제 공연 이미지가 없으면 빈약해 보이고, 정보 밀도가 필요한 예매 화면과 맞지 않는다. |
| shadcn/ui 도입 | 빠르지만 토큰·프리미티브 계층을 직접 설계하는 학습 목표가 줄어든다. 접근성이 까다로운 부분만 Radix로 보완한다. |
| 글로벌 CSS 클래스 유지 | 토큰과 컴포넌트 계층이 없어 화면이 늘수록 일관성이 깨진다. |
| 바이올렛·딥 틸 브랜드 컬러 | 바이올렛은 기존 티켓 서비스와 인상이 겹친다. 딥 틸은 초록 계열이라 "선택 가능" 상태로 오해받는다. |
| SVG 공연장 도면 좌석 맵 | 좌석 데이터가 구역 × 열 × 번호 격자라 도면을 만들 근거가 없고, 키보드 탐색 구현이 DOM 그리드보다 어렵다. |
| 좌석 상태를 색으로만 구분 | WCAG 2.2 AA(1.4.1 색 사용)를 만족하지 못한다. |
| 처음부터 스냅샷 테스트 | 개편 중에는 기준 이미지가 계속 바뀌어 갱신 비용만 생긴다. |
| 부하 테스트로 대기열 화면 재현 | 무겁고 재현성이 낮다. |
| 완료 화면에 장식용 QR | 입장 기능이 없어 실제로 쓸 수 있다고 오해하게 만든다. |

## 결과

- 얻는 것:
  - 토큰 → 프리미티브 → 기능 컴포넌트 계층이 생겨 화면이 늘어도 시각 규칙이 한 곳에서 관리된다.
  - 대기열, 좌석 경합, 선점 만료가 화면에서 보인다.
  - 모바일에서 예매와 취소 전 과정을 쓸 수 있다.
- 감수하는 것:
  - web 의존이 늘어난다(`lucide-react`, Radix 일부, Pretendard 폰트 파일, `@axe-core/playwright`).
  - 기존 web E2E의 선택자와 문구 검증을 화면 변경에 맞춰 고쳐야 한다.
  - 장르 추가는 core 스키마와 API를 바꾸므로 BFF 경계 스키마도 함께 고쳐야 한다.
- 바뀌는 문서·지침:
  - [UI 가이드](../ui-guide.md): 디자인 방향, 시각 규칙, 화면별 구성을 이 결정으로 다시 씀
  - [프런트엔드 지침](../rules/frontend.md): 문구 톤 규칙 추가
  - 신설: [UI 개편 로드맵](../ui/roadmap.md)
  - `AGENTS.md` 1절·3절: U 트랙 병행
  - `docs/architecture.md`는 장르 컬럼이 구현될 때 함께 고친다.

## 검증

- `@axe-core/playwright` 검사를 web E2E에 붙여 주요 화면의 WCAG 위반을 잡는다.
- 전체 흐름 캡처 스크립트로 모바일(390px)과 데스크톱(1440px) 화면을 확인하고, U5에서 `toHaveScreenshot()` 기준 이미지 테스트로 전환한다.
- web 단위 테스트로 좌석 그리드의 방향키 이동과 상태별 레이블을 검증한다.
