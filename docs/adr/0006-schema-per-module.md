# 0006. 모듈별 스키마 분리, 스키마 간 조인 금지

- 상태: 수락
- 일자: 2026-11-10

## 맥락

추후 MSA로 전환한다. 서비스 분리에서 가장 떼기 어려운 것은 코드가 아니라 조인과 외래 키로 얽힌 테이블이다.

## 검토한 대안

- (a) PostgreSQL 인스턴스 하나, 모듈별 스키마 분리, 모듈 간 외래 키·조인 금지
- (b) 스키마 하나에 테이블 접두어로만 구분

## 결정

**(a)** 로 한다. 스키마는 `member`, `catalog`, `booking`, `payment`, `settlement`. 다른 모듈의 데이터는 ID 참조와 이벤트로만 접근한다.

정산 집계에는 여러 모듈의 데이터가 필요하므로, `settlement`가 이벤트로 받아 **자기 스키마에 쌓은 사본**을 읽는다.

## 결과

- MSA 전환 시 데이터베이스 분리가 스키마 단위 이전으로 끝난다.
- 모듈 간 참조 무결성을 DB가 보장하지 않는다. 애플리케이션과 이벤트로 일관성을 맞춰야 한다.
- `settlement`의 사본은 원본과 시차가 있을 수 있다. 결제 대사 Batch가 불일치를 검출한다.
