## 배경

현재 core가 예매 확정·취소 이벤트의 정산 사본을 저장하고, core-batch가 이 사본에서 일별 정산을 계산한다. Kafka 외부화 이전 사본과 이미 계산한 결과를 보존해야 전환 뒤에도 기존 정산 조회가 이어진다. core의 배치 메타데이터는 정산 외에 미결제 예매 정리 등 다른 Job의 실행에도 쓰인다.

## 결정

1. 같은 PostgreSQL 인스턴스에 전용 계정과 `settlement_db`를 둔다. 정산 데이터와 전환 이후의 정산 배치 메타데이터는 이 DB가 소유한다.
2. 점검 창에 새 정산 배치 실행과 예매 상태를 변경하는 쓰기를 멈추고, 진행 중인 실행과 미완료 정산 이벤트를 정리한다. 판매·환불 사본과 일별 정산 결과를 모두 옮겨 건수와 내용을 대조한 뒤 새 소비를 시작한다. 적재를 검증한 후 조회와 배치를 전환한다.
3. 기존 정산 배치 실행 이력은 core DB에 보관한다. 이전 Job의 재시작은 전환 전에 마무리하고, 신규 실행 이력은 `settlement_db`에서 시작한다.

## 검토한 대안

| 대안 | 채택하지 않은 이유 |
| --- | --- |
| 두 DB에 쓰면서 무중단 전환 | 두 쓰기 경로의 진행 상태와 데이터 차이를 전환 중에 지속적으로 맞춰야 한다. 점검 창을 확보하면 쓰기가 멈춘 시점에 데이터를 대조할 수 있다. |
| 기존 정산 배치 실행 이력까지 복사 | 공용 배치 테이블에서 정산 실행만 골라 실행·스텝·컨텍스트와 참조를 함께 옮겨야 한다. 진행 중인 실행을 전환 전에 마무리하면 새 DB에서 옛 체크포인트를 이어갈 필요가 없다. |

## 결과

- 얻는 것: 과거 판매·환불 사본과 일별 정산 결과를 보존하고, 정산 DB의 접근 권한과 신규 실행 이력을 독립시킨다.
- 감수하는 것: 전환 중 쓰기 중단이 필요하다. 전환 전후의 배치 실행 이력을 확인할 때는 실행 시점에 해당하는 DB를 조회한다.
- 바뀌는 문서·지침: [아키텍처의 배포 단위](../architecture.md#배포-단위)에 전환 결정을 기록한다. 정산 앱과 배치의 실행 지침 및 런북은 구현과 함께 갱신한다.

## 검증

격리된 PostgreSQL에서 이전 전후 정산 테이블의 건수와 체크섬을 대조한다. 기존 정산 배치 이력이 core DB에 남고 신규 실행 이력은 정산 DB에 저장되는지 확인한다. 분리한 환경에서 `BatchBaselineE2eTests`의 정산 기준선과 주최자 조회 결과를 검증한다.
