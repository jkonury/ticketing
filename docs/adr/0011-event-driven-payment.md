# 0011. 결제는 이벤트 기반, 만료 후 결제는 자동 환불

- 상태: 수락
- 일자: 2026-11-10

## 맥락

좌석 선점(Redis, TTL 5분)과 DB 확정 사이에 결제가 끼어 있어 실패 경로가 여러 개 생긴다. `booking`과 `payment`는 추후 분리될 1순위 모듈이다.

## 검토한 대안

- (a) `booking`이 결제 요청 이벤트를 발행하고 `payment`가 결과 이벤트로 응답
- (b) `booking`이 `payment`를 직접 동기 호출

## 결정

**(a) 이벤트 기반**으로 한다.

예매 상태는 4개로 둔다.

```
PENDING ──결제 성공──▶ CONFIRMED ──사용자 취소·환불──▶ CANCELLED
   │
   ├──시간 초과──▶ EXPIRED
   └──사용자 취소──▶ CANCELLED
```

- 결제 요청에는 **멱등 키**를 두어 PG의 중복 웹훅을 걸러낸다.
- 결제는 성공했는데 선점이 이미 만료된 경우 **자동 환불**한다.
- 결제 실패 시 좌석을 반환한다.

## 결과

- 이 구조가 MSA 전환 시 Saga로 그대로 이어진다.
- 예매 요청의 응답 시점에는 결제 결과를 알 수 없다. 클라이언트는 예매 상태를 조회하거나 통지를 받아야 한다.
- 실패 경로(결제 실패, 웹훅 중복, 웹훅 지연)를 테스트로 검증해야 한다.
