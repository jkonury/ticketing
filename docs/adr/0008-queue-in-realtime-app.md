# 0008. 대기열은 실시간 앱 소유, 입장 토큰은 Gateway가 검증

- 상태: 수락
- 일자: 2026-11-10

## 맥락

예매 오픈 시 몰리는 트래픽을 코어 앞에서 줄 세워야 한다.

## 검토한 대안

- (a) Redis Sorted Set 대기열. 실시간 앱이 순번을 SSE로 push하고, 차례가 되면 짧은 수명의 입장 토큰을 발급한다. Gateway가 예매 API에서 토큰을 검증한다.
- (b) 대기열 없이 Gateway rate limit만 적용
- (c) (a)와 같되 토큰 검증을 코어 앱에서 수행

## 결정

**(a)** 로 한다. 대기열(`queue`)은 코어의 모듈이 아니라 실시간 앱이 소유한다.

## 결과

- 코어는 대기열의 존재를 모른다. 대기열 정책을 바꿔도 코어는 영향받지 않는다.
- Gateway에 라우팅 외의 실제 역할(입장 토큰 검증 필터)이 생긴다.
- 입장하지 않은 요청은 코어에 도달하기 전에 차단된다.
- (b)는 사용자에게 순번을 보여줄 수 없고 공정한 순서를 보장하지 못한다.
- Gateway를 우회해 코어에 직접 접근할 수 없도록 네트워크를 구성해야 한다.
