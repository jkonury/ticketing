# ADR 0052: 관리자 개입 상태 — 공연 판매 중지와 회원 이용 정지

- 상태: 합의
- 작성일: 2026-11-28
- 합의일: 2026-11-28
- 결정 주체: 2026-11-28 관리자 기능 강화 설계 인터뷰(Q5~Q14)
- 대체: 없음
- 대체됨·일부 변경: 없음
- 관련: [ADR 0034](0034-platform-admin-role-and-audit.md), [ADR 0013](0013-jwt-behind-bff.md), [ADR 0035](0035-coupon-module-reservation-saga.md), [아키텍처](../architecture.md)

## 배경

관리자 기능은 회원 역할 변경, 쿠폰 관리, 감사 로그 조회뿐이다. 운영자는 문제가 있는 공연을 내리거나 악성 회원을 막을 수단이 없고, 예매·결제를 한곳에서 볼 수도 없다. `Performance`와 `Member`에는 상태 필드가 없어 상태 개념과 이를 다른 모듈에 전달할 방법을 정해야 한다. 규칙 1·2에 따라 모듈 간 전달은 이벤트로만 하고 스키마를 넘는 조인은 금지된다. 강한 개입(예매 강제 취소·환불, 공연 취소)은 booking·payment·coupon을 가로지르는 Saga라 이번 범위에서 제외한다.

## 결정

1. 공연에 상태 `ACTIVE`/`SUSPENDED`를 둔다. 판매 중지는 공개 목록·상세 노출(상세는 404)과 신규 좌석 선점·예매 생성, 주최자의 공연 수정·회차 추가를 막는다. 이미 만든 PENDING 예매의 결제, CONFIRMED 예매 조회·취소는 가능하다. 주최자는 전용 상세 API(`GET /api/v1/organizer/performances/{id}`)에서 판매 중지된 자기 공연도 조회할 수 있다. 판매 현황과 정산도 확인할 수 있다.
2. 공연 상태 변경은 catalog가 이벤트로 발행하고 booking이 `schedule` 사본에 반영한다. 기존 catalog→booking 사본 경로를 쓰고 상태 번호로 이벤트의 재전달과 순서 역전을 처리한다.
3. 회원에 상태 `ACTIVE`/`SUSPENDED`를 둔다. 이용 정지는 로그인과 토큰 갱신을 거부하고 해당 회원의 refresh 토큰을 전부 폐기한다. 이미 발급된 access 토큰은 만료까지 유효하며(ADR 0034 결정 4와 같은 감수) 진행 중 예매·결제는 건드리지 않는다.
4. 정지·중지는 사유(필수, 최대 200자)를 받아 감사 로그에만 남기고 회원·주최자에게 노출하지 않는다. 해제·재개는 사유를 받지 않는다.
5. 자기 자신과 `ADMIN` 역할 회원은 정지할 수 없다. 같은 상태로 다시 바꾸는 요청은 409로 거부한다.
6. 공연 판매 중지·재개와 회원 이용 정지·해제는 이벤트로 발행하고 audit가 `admin_action`에 멱등으로 기록한다(ADR 0034 결정 5와 같은 방식). 조회는 기록하지 않는다.
7. 예매·결제 조회는 core(`/api/v1/admin/bookings`)와 payment 앱이 각각 제공하고 BFF가 예매 상세에서만 `bookingId`로 합친다. 결제 단독 목록은 만들지 않는다.
8. 관리자 역할은 `ADMIN` 하나로 유지한다.

## 검토한 대안

| 대안 | 채택하지 않은 이유 |
| --- | --- |
| 판매 중지 시 PENDING 예매도 정리 | 진행 중 결제를 끊으면 결제 성공·예매 실패 보상 경로가 새로 생긴다. 공연 취소 Saga와 함께 다룬다. |
| 요청마다 정지 여부를 검사해 access 토큰도 즉시 무효화 | Gateway·core 조회·캐시 비용이 크고 JWT 검증 경로의 성능 목표에 영향이 있다. |
| payment 사본을 core에 쌓아 한 곳에서 조회 | 새 사본 저장소와 동기화 비용이 생긴다. 합치는 지점이 상세뿐이라 필요 없다. |
| 읽기 전용 관리자 역할·권한 단위 도입 | 규모에 비해 비용이 크다. 필요해지면 새 ADR로 다룬다. |

## 결과

- 얻는 것: 문제 공연·회원을 막는 수단, 예매·결제 가시성, 상태 변경의 감사 추적.
- 감수하는 것: 정지 후 access 토큰 잔여 수명, 판매 중지 후 기존 PENDING 예매의 결제 진행, 두 도메인의 상태 컬럼·이벤트 계약 추가.
- 바뀌는 문서·지침: [용어사전](../glossary.md)(반영함). 구현 단계에서 `docs/architecture.md`의 audit 이벤트·API 표와 이벤트 카탈로그를 같은 변경에서 고친다.

## 검증

정지 회원의 로그인·토큰 갱신 거부, 판매 중지 후 신규 예매 거부와 기존 예매의 결제·취소, 주최자 상세 API의 소유권 검사, 감사 로그의 멱등과 모듈 경계 검증을 [구현 계획](../workflow/plans/2026-11-28-admin-enhancement.md)에 명시했다.
