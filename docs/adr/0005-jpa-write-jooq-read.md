# 0005. 쓰기는 JPA, 조회는 jOOQ

- 상태: 수락
- 일자: 2026-11-10

## 맥락

JPA와 jOOQ를 함께 쓴다. 역할이 겹치면 같은 데이터를 두 방식으로 다루게 되어 혼란스럽다.

## 검토한 대안

- (a) 명령(쓰기)은 JPA, 조회(목록·통계·정산 집계)는 jOOQ
- (b) 모듈별로 하나씩 선택 (예: `booking`은 JPA, `settlement`는 jOOQ)
- (c) 기본은 JPA, 복잡한 쿼리만 jOOQ

## 결정

**(a)** 로 한다. 헥사고날 모듈에서는 출력 포트를 `CommandPort`와 `QueryPort`로 나누고 어댑터를 각각 JPA, jOOQ로 구현한다. 스키마는 Flyway로 관리하고 jOOQ 코드는 그 스키마에서 생성한다.

## 결과

- 어느 기술을 쓸지에 대한 기준이 명확하다. (c)는 "복잡한 쿼리"의 기준이 모호하다.
- 조회에서 JPA 연관 탐색으로 인한 N+1 문제를 피한다.
- 테이블 하나에 대해 JPA 엔티티와 jOOQ 생성 코드가 모두 존재한다. 마이그레이션 변경 시 둘 다 맞춰야 한다.
