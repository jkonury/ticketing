# 0001. 도메인은 지정석 공연 티켓 예매

- 상태: 수락
- 일자: 2026-11-10

## 맥락

사용할 스택이 먼저 정해져 있었다: WebMVC + Virtual Thread, WebFlux + Coroutines, SSE, Security, Batch, API Gateway, Modulith, JPA, jOOQ, 헥사고날, Redis, PostgreSQL, Next.js BFF, 추후 MSA + k8s. 목적은 학습 겸 포트폴리오이므로, 스택의 각 요소가 억지 없이 필요해지는 도메인이 기준이다.

## 검토한 대안

| 후보 | 평가 |
|---|---|
| A. 공연/티켓 예매 | 대기열, 좌석 선점, 결제, 정산이 모듈 경계로 깔끔하게 나뉜다. 모든 스택 요소에 실제 용도가 있다. 국내 포트폴리오에서 흔한 주제라는 단점이 있다. |
| B. 실시간 경매 마켓 | 입찰 스트림, 마감 Batch 등 적합도가 높고 차별화에 유리하다. |
| C. 주문/배달 플랫폼 | 적합하지만 범위가 넓어 1인 프로젝트로는 핵심이 흐려지기 쉽다. |
| D. 자산/가계부 통합 | BFF 조합에는 좋으나 동시성 문제가 약하다. |

좌석 모델도 함께 검토했다.

- 지정석: 좌석 단위 선점 경쟁이 생긴다.
- 등급별 수량제: 일반적인 재고 차감 문제라 차별점이 적다.
- 둘 다 지원: 범위가 늘어난다.

## 결정

**A. 공연/티켓 예매, 지정석**으로 한다.

## 결과

- 트랜잭션 중심 코어(예매·결제)와 실시간 팬아웃(대기열·좌석 현황)이 자연스럽게 분리되어 MVC와 WebFlux를 모두 쓸 이유가 생긴다.
- 흔한 주제이므로 차별점은 구현 깊이(동시성 검증, 실패 경로, 부하 테스트 수치)에서 만든다.
- 등급별 수량제는 미룬다.
