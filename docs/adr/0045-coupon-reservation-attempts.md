# ADR 0045: 쿠폰 예약 시도 식별과 재전달

- 상태: 합의
- 작성일: 2026-11-21
- 관련: [ADR 0035](0035-coupon-module-reservation-saga.md), [이벤트 카탈로그](../architecture/events.md)

## 배경

쿠폰 해제 직후 같은 예매에 같은 쿠폰을 적용하면 Modulith가 두 요청을 어느 순서로든 처리할 수 있다. 기존의 주문·쿠폰 식별자만으로는 어느 적용에서 온 결과나 해제인지 구분할 수 없다. 해제가 끝나면 발급 쿠폰의 주문 정보도 지워져 과거 예약 요청을 재전달했을 때 다시 예약될 수 있다.

## 결정

- 예매마다 단조 증가하는 `reservationAttemptId`를 저장한다. 쿠폰을 새로 적용할 때 증가시키고 제거 후에도 마지막 값을 보존한다. 예매의 낙관적 락으로 동시 적용을 직렬화한다. 예약 요청, 예약 성공·거절, 해제 요청, 사용 확정에 같은 ID를 전달한다.
- 쿠폰은 발급 행에 현재 예약 시도 ID를 저장하고 `coupon.reservation_attempt`에 발급 쿠폰·주문별 가장 높은 시도와 결과를 보존한다. 발급 행 잠금 안에서 시도 기록과 상태 갱신을 같은 트랜잭션으로 처리한다. 같은 주문의 새 시도는 이전 예약을 승계할 수 있고, 다른 주문의 예약은 유지된다. 명시적 해제가 먼저 도착하면 그 시도를 종료 기록으로 남긴다. 종료·거절된 시도와 더 낮은 시도의 요청은 다시 예약하지 않는다.
- 예매는 쿠폰과 시도 ID가 모두 일치하는 대기 결과만 반영한다. 이미 반영한 성공은 그대로 두고, 과거 성공에 대한 보상은 그 시도 ID로만 해제를 요청한다.
- 사용 확정과 명시적 해제는 해당 시도에 적용한다. 정리 Job은 잠근 행의 만료 시각을 재검사하고 실제 해제된 시도를 함께 기록한다. 정리로 해제된 시도의 늦은 사용 확정은 해제 직후와 발급 행 버전이 같을 때만 복구하고 불일치를 기록한다. 재예약·회수·사용으로 버전이 바뀌면 과거 확정은 현재 상태를 변경하지 않는다. 신규 시도의 명시적 해제는 종료로 취급한다.
- 기존 행과 ID 없는 JSON은 시도 `0`으로 합류한다. 마이그레이션은 예약·사용된 발급 행의 시도 기록을 채운다. 기존에 이미 해제된 행에는 주문 이력이 없으므로 미완료 요청의 첫 재전달은 정상 경로로 처리하고, 예매의 시도 일치 검사 및 해제 보상으로 정리한다. 기록이 없는 발급 행의 구형 사용 확정과 구형 만료 해제의 사용 확정은 기존 복구 동작을 유지한다. 후자는 실제 해제 직후의 행 버전이 같을 때만 적용한다. 배포 시 core와 core-batch를 함께 교체한다.

## 검토한 대안

| 대안 | 채택하지 않은 이유 |
| --- | --- |
| 새 예약을 앞선 해제가 끝날 때까지 지연 | 비동기 처리 순서와 재전달에 예매의 진행이 의존한다. |
| 발급 행의 현재 시도 ID만 비교 | 해제 후 다른 주문이 쿠폰을 쓰고 나면 이전 주문에서 온 예약 요청을 식별할 수 없다. |
| 요청 시각으로 순서 비교 | 같은 시각의 요청과 인스턴스 간 시계 차이를 처리해야 한다. 예매에서 저장하는 증가값으로 순서를 결정한다. |

## 결과

쿠폰을 뗐다 다시 붙이는 두 처리 순서가 같은 예약·할인 상태로 수렴한다. 주문별 마지막 시도 기록은 과거 이벤트 재전달을 차단하기 위해 유지한다.
