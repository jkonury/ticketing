## 배경

예매 경로는 회차 ID만 포함하지만 좌석 선택과 완료 화면에는 공연 제목과 회차 시각이 필요하다. 기존 좌석 조회는 이 정보를 제공하지 않는다.

## 검토한 대안

- 공연 전체를 순회하고 상세별 회차를 검색하면 요청 수가 공연 수에 따라 증가한다.
- 링크에 공연 ID를 추가하면 예매 경로의 진입 계약이 바뀌고 전달된 ID와 회차가 일치하는지 확인해야 한다.

## 결정

catalog에 공개 `GET /api/v1/schedules/{id}`를 추가한다. 해당 모듈의 스키마만 조회하여 `id`, `performanceId`, `performanceTitle`, `startsAt`을 반환하며, 없는 회차는 404 `SCHEDULE_NOT_FOUND`다.

## 결과

BFF는 회차 ID로 필요한 정보를 고정된 횟수의 조회로 얻으며 예매 경로를 유지한다. 코어 API가 하나 늘어난다.

## 검증

catalog 통합 테스트에서 공개 조회와 존재하지 않는 회차를 검증하고 웹 예매 흐름에서 이 정보를 사용한다.
