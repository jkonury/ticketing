# 0012. 결제 연동은 가짜 PG로 시작

- 상태: 수락
- 일자: 2026-11-10

## 맥락

결제의 멱등성과 보상 처리(결제 실패 시 좌석 반환, 만료 후 결제 시 환불)를 검증하려면 지연, 타임아웃, 중복 웹훅 같은 비정상 상황을 재현할 수 있어야 한다.

## 검토한 대안

- (a) 실제 PG(토스페이먼츠 등)의 테스트 모드 연동
- (b) 가짜 PG 서버를 직접 만들어 지연·실패·중복 콜백을 재현

## 결정

**(b) 가짜 PG**로 시작한다. 별도 배포 단위 `fake-pg`로 두고, 지연·타임아웃·실패·중복 웹훅을 설정으로 제어한다. 결제 대사 Batch가 쓸 거래 내역 조회 API도 제공한다.

알림(이메일/SMS)은 실제 발송 없이 로그 출력으로 시작한다.

## 결과

- 비정상 상황을 원하는 대로 만들 수 있어 실패 경로 테스트가 쉽다.
- 실제 PG의 API 형태나 인증 방식은 다루지 않는다.
- PG 연동은 `payment`의 출력 포트로 추상화하므로, 나중에 실제 PG 어댑터를 추가할 수 있다.
