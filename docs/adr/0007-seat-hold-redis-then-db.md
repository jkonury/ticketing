# 0007. 좌석은 Redis 선점 후 DB 확정

- 상태: 수락
- 일자: 2026-11-10

## 맥락

지정석에서는 좌석 하나를 두 명이 동시에 잡으면 안 된다. 또한 좌석을 고른 뒤 결제를 마칠 때까지 일정 시간 좌석을 붙들어 둘 수 있어야 한다.

## 결정

2단계로 처리한다.

1. **임시 선점 (Redis)**: 좌석별 `SET NX` + TTL. 여러 좌석은 Lua 스크립트로 전부 성공하거나 전부 실패하게 한다.
2. **최종 확정 (DB)**: 결제 성공 시 기록한다. `(회차, 좌석)` 유니크 제약이 마지막 방어선이다.

규칙 값은 다음과 같다.

| 항목 | 값 | 검토한 값 |
|---|---|---|
| 선점 유지 시간 | 5분 | 5분 / 7분 / 10분 |
| 1회 예매 최대 좌석 수 | 4매 | 2매 / 4매 |

## 결과

- 선점 경쟁이 DB까지 가지 않아 코어의 부하가 줄어든다.
- 만료는 Redis TTL이 자동으로 처리한다.
- Redis와 DB는 하나의 트랜잭션이 아니다. 다음 경로를 따로 다뤄야 한다.
  - DB 커밋 실패 시 Redis 선점 되돌리기
  - Redis TTL은 지났는데 예매가 `PENDING`으로 남은 경우: 미결제 예매 정리 Batch가 보정
  - 선점 만료 후 결제가 성공한 경우: 자동 환불 ([0011](0011-event-driven-payment.md))
- Redis 선점에 문제가 있어도 DB 유니크 제약 때문에 중복 판매는 일어나지 않는다.
