# 0013. 자체 JWT 발급, 토큰은 BFF가 보관

- 상태: 수락
- 일자: 2026-11-10
- 일부 변경: 역할 구성(플랫폼 관리자 미도입)은 [ADR 0034](0034-platform-admin-role-and-audit.md)에서 ADMIN을 추가하는 것으로 바뀌었다

## 맥락

Next.js BFF의 역할 중 하나가 인증/보안(토큰 관리)이다. 토큰을 누가 발급하고 어디에 둘지 정해야 한다.

## 검토한 대안

- (a) 코어의 `member` 모듈이 직접 JWT(access/refresh)를 발급한다. BFF가 토큰을 httpOnly 쿠키 세션 뒤에 숨기고 갱신을 담당한다.
- (b) Spring Authorization Server를 별도 앱으로 두고 OAuth2/OIDC를 쓴다. BFF는 OAuth2 client가 된다.
- (c) Keycloak 같은 외부 IdP를 쓴다.

## 결정

**(a)** 로 한다. 소셜 로그인은 나중에 추가한다.

역할은 일반 사용자와 주최자 두 가지로 한다. 플랫폼 관리자는 두지 않는다.

## 결과

- BFF 패턴의 핵심(토큰을 브라우저에 주지 않음, 서버 측 갱신)을 직접 구현한다.
- 배포 단위가 늘지 않는다.
- 브라우저에는 세션 쿠키만 있으므로 XSS로 토큰이 탈취되지 않는다. 대신 쿠키 기반이므로 CSRF 방어가 필요하다.
- BFF가 세션 상태를 갖는다. BFF를 여러 인스턴스로 띄우려면 세션 저장 방식을 정해야 한다.
- (b)는 MSA 전환 시점에 다시 검토한다.
