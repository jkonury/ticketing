# ADR 0036: 정산 정가 기준과 플랫폼 할인 부담

- 상태: 합의
- 작성일: 2026-11-17
- 합의일: 2026-11-17
- 결정 주체: 2026-11-17 M5.5 설계 인터뷰(Q3, Q7)
- 대체: 없음
- 대체됨·일부 변경: 없음
- 관련: [계획](../backup/plans/m5-5-coupon.md), [ADR 0035](0035-coupon-module-reservation-saga.md)

## 배경

쿠폰은 플랫폼이 발행하므로 할인액도 플랫폼이 부담한다. 주최자는 쿠폰 사용 여부와 무관하게 정가 기준으로 정산받아야 한다. 현재 정산은 예매 확정액으로 판매액을 집계하는데, 쿠폰이 붙으면 결제액과 정가가 달라진다.

## 결정

1. 판매액과 수수료는 정가(`listAmount`) 기준으로 계산한다. 주최자 정산은 쿠폰의 영향을 받지 않는다.
2. 정산 판매 기록에 `listAmount`와 `discountAmount`를 함께 저장하고, 일별 정산에 `platformDiscountAmount`(판매분 할인 합)를 기록한다. 기존 행은 기존 금액으로 채운다.
3. 환불은 정가 기준으로 차감하며, 환불된 예매의 할인 부담은 차감하지 않는다. 쿠폰이 소멸하므로 플랫폼 비용으로 확정한다.
4. 결제 대사는 실결제액(`payableAmount`) 기준으로 유지한다. PG가 받은 금액과 맞춰야 하기 때문이다.
5. 주최자 조회 API에는 할인 부담액을 노출하지 않는다.

## 검토한 대안

| 대안 | 채택하지 않은 이유 |
| --- | --- |
| 실결제액 기준 정산 | 쿠폰 부담이 주최자에게 전가되고, 수수료 기준이 쿠폰에 따라 달라진다. 플랫폼 부담 원칙(Q3)과 어긋난다. |
| 할인액을 주최자와 분담 | 분담 비율·합의 규칙이 새로 필요하고 이번 범위(플랫폼 발행·부담)를 넘는다. |
| 환불 때 할인 부담을 되돌림 | 소멸한 쿠폰을 되돌릴 근거가 없고, 정산 정정 규칙이 늘어난다. |
| 대사도 정가 기준으로 변경 | PG 금액과 맞지 않아 대사가 깨진다. |

## 결과

- 얻는 것: 주최자 정산 불변, 플랫폼 할인 비용을 별도로 집계할 수 있다.
- 감수하는 것: 정산과 대사가 서로 다른 금액 기준을 쓴다. 환불이 많으면 플랫폼 할인 부담이 정산 기록상 줄지 않는다. 정산 테이블 마이그레이션이 필요하다.
