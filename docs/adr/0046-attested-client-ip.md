# 0046. 비회원 요청의 클라이언트 IP 신뢰 경계

- 상태: 수락
- 일자: 2026-11-21
- 관련: [ADR 0020](0020-gateway-verification-contracts.md), [인증·BFF 연동](../architecture/integrations.md)

## 맥락

개발 환경에서는 nginx, BFF, 직접 호출이 같은 호스트에서 Gateway에 연결된다. 전달 헤더 개수나 루프백 주소만으로는 어느 서버가 요청을 보냈는지 구별할 수 없다.

## 결정

| 경로 | 비회원 버킷에 쓰는 주소 |
| --- | --- |
| 클라이언트 → Gateway | Gateway가 수락한 TCP 연결 주소 |
| 클라이언트 → nginx → Gateway | nginx에서 확인한 연결 주소 |
| 클라이언트 → nginx → web → Gateway | nginx가 제공하고 BFF와 Gateway가 각각 검증한 주소 |
| 클라이언트 → web → Gateway | nginx 증명이 없으므로 Gateway가 수락한 BFF 연결 주소 |

- nginx는 외부에서 온 전달 주소 헤더를 지우거나 덮어쓰고, 자신의 연결 주소와 서버 전용 공유 비밀을 각각 `X-Ticketing-Client-IP`와 `X-Ticketing-Ingress-Proof`에 넣는다. nginx는 외부 헤더로 연결 주소를 다시 쓰는 설정 없이 동작한다.
- BFF는 비밀이 일치하고 단일 IPv4/IPv6 리터럴인 경우에만 새 전달 헤더를 만든다. SSR, Server Action, Route Handler의 비회원 Gateway 호출에 공통으로 적용한다. 증명이 붙은 공개 조회는 요청별로 수행하고 나머지 공개 조회의 재검증 설정은 유지한다.
- Gateway는 서버의 자동 전달 헤더 해석을 끄고, 비밀이 일치하는 단일 IP만 사용한다. 증명 누락·불일치, 주소 누락·오류 때는 TCP 연결 주소로 폴백한다. 전달 주소와 증명 헤더는 하위 앱으로 보내기 전에 제거한다. 인증 회원은 기존 회원 버킷을 사용한다.
- 비밀은 32바이트 난수를 64자리 소문자 16진수로 표현한다. nginx, BFF, Gateway를 관리하는 서버에서만 공유한다. nginx upstream은 같은 호스트의 루프백을 사용한다. 다른 호스트로 옮길 경우 보호된 서버 간 전송이 필요하다. 비밀이나 요청 헤더 전체를 로그·브라우저·저장소에 노출하지 않는다.

## 검토한 대안

| 대안 | 현재 배치에서의 제약 |
| --- | --- |
| 신뢰 프록시 홉 수 또는 연결 주소 목록 | nginx와 직접 호출이 같은 루프백 주소로 들어온다. |
| ingress 전용 포트 또는 별도 네트워크 | nginx, BFF, Gateway의 실행 토폴로지를 바꿔야 한다. |

## 검증

합성 주소로 직접 연결의 버킷 유지, 증명된 주소별 버킷 분리, IPv6 정규화, 잘못된 전달값의 폴백, 하위 요청에서 헤더 제거를 검증한다.
