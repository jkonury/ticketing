# Notes 검증 지도

이 디렉터리는 Notes의 사용자 대상 동작을 검증하는 데 쓰는, 관리되는 원천이다. 앱을 구동하기 전에 이 색인을 읽고, 해당하는 기능 파일을 절차로 쓴다. (가상의 앱 Notes로 만든 **형식 예시**다. 실제 지도는 이 저장소의 앱 기준으로 쓴다.)

## 기준 전제

- Notes를 `http://127.0.0.1:4173`에서 일회용 데이터 디렉터리로 띄운다.
- 동시 실행이 상태를 공유하지 않도록 `NOTES_DATA_DIR=/tmp/notes-verify-$RUN_ID`를 설정한다.
- `Quarterly plan`, `Grocery list`라는 제목의 노트를 시드한다.
- `control-notes`와 `notes` CLI를 `PATH`에 둔다.
- `control-notes doctor`를 실행해 기대한 URL, 데이터 디렉터리, 빌드 리비전을 요구한다.
- 이번 검증 실행이 시작하지 않은 인스턴스는 구동하지 않는다.

## 구동 규약

- 전제가 달리 말하지 않으면 모든 절차를 기준 상태에서 시작한다.
- CSS 선택자나 DOM 위치보다 ARIA 역할과 접근 가능한 이름을 쓴다.
- 모든 명령은 글자 그대로 취급한다. 따옴표 안의 이름과 플래그를 바꾸지 않는다.
- 브라우저 동작은 `control-notes browser`로, 터미널 동작은 `control-notes cli -- <명령>`으로 실행한다.
- 변경 후에는 시드 데이터를 복원한다. 정리에서 증거 파일을 지우지 않는다.

## 증명과 건너뜀 보고

- 마지막 화면만이 아니라 사용자 동작과 그 결과 상태를 남긴다.
- UI 증명에는 ARIA 스냅샷과 앱 정체가 보이는 스크린샷을 포함한다.
- CLI 증명에는 명령, stdout, stderr, 종료 코드를 포함한다.
- 변경 증명에는 저장된 값을 읽기 전용으로 다시 본 화면을 포함한다.
- 모든 증거에 기능 ID와 사용한 진입점을 기록한다.
- 도달하지 못한 경로는 시도한 명령과 충족되지 않은 전제로 보고한다.
- 건너뛴 진입점을 다른 경로로 검증했다고 보고하지 않는다.

## 기능 항목 규약

각 기능 파일은 H1 제목과 사용자에게 보이는 동작을 설명하는 문단 하나로 시작한다. 그다음 H2 네 개를 정확히 이 순서로 쓴다.

1. `Sub-features`: 짧은 ID와 동작 한 줄씩.
2. `How to get to it (user POV)`: 사용자가 쓰는 모든 진입점.
3. `Driving it with <하네스>`: `Preconditions:`로 시작하고, 사용자 동작마다 정확한 명령과 관찰 가능한 결과를 짝지은 라벨 붙은 항목.
4. `Gotchas`: 검증 실행을 낭비하거나 무효로 만들 수 있는 함정.

지도에는 구현 세부를 쓰지 않는다. 사용자 경로, 안정적인 핸들, 필요한 상태, 명령, 관찰 가능한 증거만 적는다.
