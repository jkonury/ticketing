# 코드 스멜 기준선

Fowler 《Refactoring》 3장의 코드 스멜이다. 저장소가 문서화하지 않은 부분의 보조 기준으로만 쓴다.

- **저장소 규칙이 이긴다.** 문서화된 규칙이 허용·권장하는 것은 스멜로 지적하지 않는다.
- **항상 판단 사항이다.** "Feature Envy 가능성"처럼 휴리스틱 이름을 붙여 보고하고, 확정 위반으로 올리지 않는다.
- 린터·detekt·ktlint가 이미 강제하는 것은 건너뛴다.

각 항목은 *무엇인가* → *어떻게 고치나* 순서다. diff와 대조해 본다.

- **Mysterious Name**: 이름이 하는 일이나 담은 값을 드러내지 않는 함수·변수·타입. → 이름을 바꾼다. 정직한 이름이 안 나오면 설계가 모호한 것이다.
- **Duplicated Code**: 같은 로직 형태가 변경 안의 여러 hunk나 파일에 나타남. → 공통 형태를 추출해 양쪽에서 호출한다.
- **Feature Envy**: 자기 데이터보다 다른 객체의 데이터를 더 많이 건드리는 메서드. → 그 데이터가 있는 쪽으로 옮긴다.
- **Data Clumps**: 같은 필드·파라미터 몇 개가 항상 함께 다님(타입으로 태어나고 싶은 것). → 하나의 타입으로 묶어 넘긴다.
- **Primitive Obsession**: 고유 타입이 어울리는 도메인 개념을 원시 타입이나 문자열로 표현. → 작은 타입을 만든다.
- **Repeated Switches**: 같은 타입에 대한 `switch`·`if` 연쇄가 변경 곳곳에 반복됨. → 다형성이나 두 곳이 공유하는 맵으로 대체한다.
- **Shotgun Surgery**: 하나의 논리적 변경이 diff의 여러 파일에 흩어진 수정을 강제함. → 함께 바뀌는 것을 한 모듈로 모은다.
- **Divergent Change**: 한 파일·모듈이 서로 무관한 여러 이유로 수정됨. → 이유마다 모듈이 하나씩 바뀌도록 나눈다.
- **Speculative Generality**: 명세에 없는 필요를 위해 추가한 추상화·파라미터·훅. → 지우고, 실제 필요가 생길 때까지 인라인한다.
- **Message Chains**: 호출자가 의존하면 안 되는 긴 `a.b().c().d()` 탐색. → 첫 객체의 메서드 하나 뒤로 숨긴다.
- **Middle Man**: 대부분 다른 곳으로 위임만 하는 클래스·함수. → 없애고 실제 대상을 직접 호출한다.
- **Refused Bequest**: 상속받은 것 대부분을 무시하거나 재정의하는 하위 클래스·구현체. → 상속을 버리고 합성을 쓴다.
